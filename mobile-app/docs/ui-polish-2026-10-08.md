# Native UI polish — 2026-10-08

Refine the incumbent content-first sage system, without replacing DESIGN.md or its sidecar. Mobile gallery stays artwork-led; actual images keep their large covers, missing-image previews are more compact, counts and attachment metadata aid scanning, and filtered-empty states offer a clear reset. Management presents an honest computer pairing/retry/conflict status, never equates stored pairing with live connectivity.

Phone pairing: native Form, brief two-part instructions, secure paste input and a clear primary action. Paired sync: contextual progress/error and last success, explicit conflict selection before ordinary sync settings, advanced content explanation disclosed on demand. Keep per-resource choice separate from actual commit and disable restart while choices are pending. Version picker appears before long comparison content. No glass on reading surfaces.

Desktop companion: same native status/connection/QR/action hierarchy; QR lifecycle and generated code must agree, no network or credential architecture changes.

QA uses only owned simulator and temporary desktop data; original service and formal collections remain untouched. Capture actual light/dark/accessibility screens with CUA, then required independent finish review and documenter handoffs. No HTML/CSS detector for SwiftUI. Native input/build/runtime blockers are reported without visual approval.

## Documented adaptation

- 入口统一为 **管理 → 电脑同步**；画廊左上角电脑图标与空库“连接电脑”直接进入同一页。
- 画廊数量来自当前搜索/分类/范围结果，不含回收站。**清除筛选**只重置分类和范围；无匹配结果的 **清除搜索与筛选**同时清空搜索。真实本地图像保留 220pt 大预览，缺少本地封面/图像文件的预览为 142pt，资源间距 28pt；来源/分类可在窄宽度改为上下排列，附件数使用真实列表数量。
- 空库隐藏重复的底部采集浮层，保留“收藏第一个资源 / 连接电脑”。辅助功能字号使用原样标题与说明的紧凑文字布局，去掉大符号和多余留白，让两项操作完整位于 tab bar 之上。
- 手机同步页以系统 Form 分出配对、进度/上次成功、**需要处理**、冲突、同步方式和连接管理。“已配对”只表示保存了连接信息，不宣称实时在线。冲突显示已选择数量，比较页的选择器位于长内容前；全部选择后才提交，待选期间不显示普通重新同步入口。高级内容说明使用 DisclosureGroup。
- Mac 面板沿用普通语义表面，分为服务状态、Wi-Fi 地址/二维码、已配对设备和底部停止/完成操作。过期码不能复制，只有回环地址时禁止生成手机码；生成、停止或撤销后的二维码状态与服务响应协调。未改网络或凭据架构。

既有 `DESIGN.md` 与 `.impeccable/design.json` 保持原样。本轮增加扫描密度与原生操作分组，仍由真实资源图像提供主要颜色，鼠尾草强调只服务动作和状态，玻璃限于采集/系统操作层。此前适配记录中的固定画廊密度以本文件这次源码观察为准；未把新手机尺寸写回桌面令牌。

最终独立复审结论：**ship reviewed refinement**。本轮已审查范围延续现有内容优先、原生控件和克制鼠尾草方向；单项 P2 首次空库辅助功能字号遮挡已由最终补拍确认解决。配对标题换行与滚动后底部操作可达也已有 Text Size 8 证据。这一结论只覆盖本轮已审查微调，不批准整产品。无封面/筛选空态、同步错误/冲突完整操作、权限、手机相机扫码、最小手机、其他辅助功能组合与旧系统仍需相应证据。

最终 `build/ui-polish-ios-build.log`、`ui-polish-ios-release.log` 均为 `BUILD SUCCEEDED`，`ui-polish-core-tests.log` 记录原生核心通过；当前 arm64 签名模拟器产物的 `ui-polish-bundle-check.log` 确认 App/扩展 App Group、浅深色不透明 accent 与图标。Mac 构建及签名验证完成。桌面 `ui-polish-python-tests.log` 完整 **197 项通过**，含生产原生模型的实际 HTTP 状态恢复、Vision 在出货 Retina 尺寸解码稠密二维码，以及 DNS 绑定回归。Vision 测试不代替实体 iPhone 相机。

纠正首次超时原因：桌面 `build/diagnostic-hook/stack-*.txt` 的 Python faulthandler 证据定位到 `HTTPServer.server_bind` 调用 `socket.getfqdn(0.0.0.0)` 时反向 DNS 阻塞；不是证书初始化或并发构建问题。`TLSServer.server_bind` 最小改用 `TCPServer.server_bind`，明确填充服务名/端口，避免该查询。`tests/test_sync_listener.py` 将 getfqdn 设为失败，先证明原实现失败（`ui-polish-dns-red.log`），再由最终完整套件验证修复；不改变 TLS/配对安全架构。

Share Extension 持续空白页仍未解决，截图和核心测试不证明系统分享可用。物理 iPhone 仍需用户自己的 Apple Team，以及 Shiji/ShijiShare 两个 target 相同、可签名的 App Group；没有已签名 IPA 或真机安装/同 Wi-Fi 验证。正式收藏、原服务未改动。
