# 拾集同 Wi-Fi 手机同步

配套 Mac 候选 App 与原生 iPhone 工程在同一 Wi-Fi 双向同步收藏及附件。没有云账号；离线各自可用。Mac 需保持运行并开启同步，手机自动同步只在 App 前台调度。开发与测试使用独立候选目录和临时收藏库，未改动正式服务或数据。

## 连接

1. 安装配套候选版本。iPhone 使用 Xcode 打开 `Shiji.xcodeproj`，给 **Shiji / ShijiShare** 选择自己的同一 Apple Team，配置各自 Bundle ID 和同一个可签名的 App Group，两个 target 的 `SHIJI_APP_GROUP` 也必须一致；具体见手机 README。源码/未签名 Release 编译产物不是已签名 IPA，尚未验证实体手机安装。
2. 两端连接同一 Wi-Fi。Mac 工具栏点 **手机同步 → 开启同步**；该 HTTPS 服务每次启动默认关闭，默认端口 8784，与本机网页/浏览器采集监听分开。
3. 若有多个 **电脑地址**，选择当前 Wi-Fi 的私有 IPv4（通常 `192.168.x.x`、`10.x.x.x` 或 `172.16–31.x.x`），不要选择 `127.0.0.1`。点 **生成配对码**；重新生成会替换旧码，五分钟内有效且仅使用一次。
4. 用 iPhone 系统相机扫 Mac QR 并打开拾集，或点 **复制配对码**，在手机 **管理 → 电脑同步**粘贴；画廊左上角电脑图标也是入口。QR 是 `shiji-sync://pair` 链接，没有 App 内相机扫码器。过期后复制按钮禁用；只有 `127.0.0.1` 时不能生成手机配对码，先连接 Wi-Fi 并重新开启服务。
5. 手机点 **配对这台电脑**，允许本地网络访问，核对电脑名称，然后 **立即同步**。QR 只打开填好码的配对页；点击配对才连接。新安装的 **App 前台自动同步**默认开启，可关闭以仅手动同步。

手机状态区显示已保存的配对信息、进度和上次成功日期/时间；“已配对”不表示实时在线。失败信息归入 **需要处理**，普通失败可 **重新同步**；待选冲突时先完成选择，不重新启动比较。同步内容说明可展开查看。

## 内容与冲突

同步名称、网址、备注、完整标签、项目归属、来源授权、常用/待整理状态、回收站与附件。项目层级及智能集合由电脑管理。JSON schema 3 与备份 ZIP manifest 2 不变；备份导入只增加未有记录，而同步可更新已配对资源。

系统比较上次成功同步快照与当前两端资源；单边修改传到另一端。两端都改过、同网址不同 ID、已同步记录在一端缺失时，手机显示 **选择保留的版本**。逐项比较，选择完整 **手机版本 / 电脑版本**，全部选择后 **同步所选版本**才写入；不按时间戳抢胜或逐字段拼接。选择缺失版本将另一端记录放入可恢复回收站。同步不物理清除附件；提交前两端若又变化，会停止并要求重新比较。

冲突区显示 **已选择 x / y**；比较页把版本选择放在长内容之前。选择本身不写收藏，实际提交与选择分开。

如果电脑将另一条已有资源改成手机某条资源的网址，且与稳定 ID 发生交叉冲突，同步会停止并说明如何先在电脑恢复原记录或调整网址；两端收藏保留。

只传缺失附件，单个上限 64 MiB、一次传输上限 512 MiB，核对大小、类型和 SHA-256。同附件 ID 的不同字节会拒绝，不覆盖原文件。手机不会为了同步自动联网抓取网站封面。

前台自动同步在激活、收藏改变和定时检查时运行，编辑/导入/待选冲突暂缓。手机退至后台停止自动调度，不承诺后台完成；再次打开 App 后继续或手动重试。

## 停止与重新配对

| 动作 | 结果 |
| --- | --- |
| 手机 **断开这台电脑** | 删除手机 Keychain 凭据与同步检查点，保留收藏/附件；不撤销电脑的旧设备授权。 |
| Mac **停止同步** | 停止 HTTPS 监听、使待用配对码失效，保留设备授权及收藏；再次开启后可继续使用未失效连接。 |
| Mac **解除所有手机配对** | 撤销所有手机令牌及待用配对码，保留收藏；各手机需重新配对。 |

连接核对配对时的精确服务器证书，并以配对私有 CA 独立验证；没有 HTTP 回退、重定向或全局信任绕过。手机凭据存 Keychain，电脑设备令牌以哈希存于本机受限文件。配对码只交给自己的手机。

电脑 IP/证书更新或换资源库时，手机先断开，再使用新码配对。连接失败先检查同 Wi-Fi、电脑同步服务、本地网络权限、防火墙和是否仍用过期地址；证书错误应重新配对，不绕过验证。共享 Wi-Fi 若隔离设备也会阻止连接。

## 已验证与待验证

2026-10-08 微调的最终 Debug/未签名 Release、原生核心、当前模拟器 App Group/资产检查与 Mac 构建/签名验证通过。完整 Python 197 项通过，含实际原生 HTTP 模型、Vision 稠密二维码解码及无 DNS 监听绑定回归。此前超时由 faulthandler 定位为 `HTTPServer.server_bind` 对 `0.0.0.0` 的反向 DNS 查询阻塞；最小 `TCPServer.server_bind` 覆写绕过查询，并非证书初始化或并发构建问题。
