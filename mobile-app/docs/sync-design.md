# Phone–computer sync — 2026-10-07

User priority: 手机与电脑同步. Extend the iPhone and desktop candidates without changing the running desktop or formal database. User confirmed same-Wi-Fi local pairing. No cloud account or background daemon is implied.

Desktop candidate: ../desktop-app. The existing loopback UI and browser-extension API stay loopback-only. A separate HTTPS service, initially off, is enabled by an explicit desktop action. A five-minute single-use pairing code contains a private IPv4 address, port, exact certificate and unpredictable bootstrap secret and private authority certificate. Certificates use SHA-256, named-curve P-256 for the CA and a 2048-bit RSA leaf valid for 365 days; renew near expiry or after address changes and require re-pairing. It exchanges for a revocable device token. iPhone pins the exact leaf and validates a complete leaf/private-CA chain against its supplied private CA as the sole trust anchor; no global certificate bypass, HTTP fallback or redirects. Credentials live in Keychain, server secrets in an owner-only file. Main App requests local-network access only when pairing/syncing.

Sync is a resource-level three-way merge using the last successfully committed local/remote snapshots, not last-write-wins timestamps. Match stable IDs, then normalized URLs; every distinct-ID URL collision requires an explicit choice, including a formerly synchronized resource recreated under another ID. Concurrent distinct edits, same-URL identity collisions and missing formerly synchronized records require a visible phone/computer choice. Changes are planned before any writes; remote commit checks the complete remote revision inside the Store lock and SQLite transaction, and local apply checks the original phone snapshot under its existing file coordinator. A late share capture must not be overwritten. Recoverable trash flags travel; sync never physically purges records or attachment bytes. Advanced collection metadata and smart collections remain desktop-owned; phone project membership is preserved.

Transfer only missing immutable attachment bytes, each capped at 64 MiB with SHA-256/size/type verification. Staged uploads never replace existing attachment files; metadata commit validates all references and rolls back newly published bytes if the SQLite transaction fails. A sync transfer is capped at 512 MiB. Retry receipts prevent duplicate writes after a lost response. Library identity prevents silently attaching a stored checkpoint to another database. Unpairing forgets credentials/checkpoints and preserves all resources.

Phone management gains a native computer-sync screen: paste pairing code, pair, named connection status, last successful sync, manual retry, optional foreground auto-sync, conflicts with explicit phone/computer choices, disconnect. Auto-sync runs while the app is active, reacts to local changes and app activation, pauses during import/edit conflicts and never blocks collection or runs indefinitely in background. No credentials appear in logs.

Verification: temporary desktop/mobile libraries only, no port8765/8783 services. Foundation merge tests cover first sync, both directions, duplicates, trash, exact tags, concurrency and conflicts. Python tests cover TLS/pair expiry/reuse/token revocation, revision races, transaction rollback, bounded hash-checked immutable attachments and idempotency. A real HTTPS desktop–Swift client integration exercises repeated bidirectional edits and attachments. Existing Python/Node and mobile core suites, iOS Debug/unsigned Release and macOS builds must pass. Native UI captures and independent finish/documentation handoffs are required where the native input surface permits them; blocked interaction is reported, never inferred from compilation.
