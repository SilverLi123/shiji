### 三、任务一：建立内容驱动的封面设计系统

现有 V5 已支持 GitHub、Motion、3D、Components 等不同海报构图，但同类资源之间可能仍有较强的视觉重复。

需要增强其内容驱动能力。

依据资源实际信息：

- 标题
- 描述
- 网站域名
- 资源类型
- 标签
- 分类
- 代码语言
- 已有真实图片
- 用户配置

选择合适的封面设计。

例如：

GitHub 仓库：偏开发者视觉、代码、技术排版。

AI 模型：偏科技图形、抽象结构和模型相关信息。

UI 组件库：偏组件展示、几何排版和交互视觉。

动效资源：偏空间层次、动力感和 Kinetic Typography。

设计参考：偏 Editorial、Swiss Grid 和大胆平面设计。

机器人资源：偏工程感、空间结构与技术信息。

不要仅通过 domain 的简单哈希随机决定封面。

需要建立可扩展的 Art Direction 规则系统。

但不能强制调用云端 AI，不引入付费生成 API。

默认利用现有真实元数据和本地程序化设计能力实现。

---

### 四、任务二：设计高质量封面变体

在现有 V5 美术体系上，打造经过精心设计的封面母版。

至少覆盖以下方向：

#### A. Editorial Poster

- Swiss Grid
- 大胆字体
- 高对比留白与排版
- 非对称构图
- 明确的视觉层级
- 中文与英文适配

#### B. Spatial Composition

- 3D 几何体
- 景深与层次
- 空间构图
- 适当的玻璃、光影和透视
- 保留现有 Spatial Design 语言

#### C. Code / Developer

- 技术信息图形化
- 代码片段
- Terminal / Syntax 元素
- 网格与数据可视化元素
- 适合 GitHub、开发工具和算法收藏

#### D. Kinetic / Motion

- 动态字体
- 运动轨迹
- 程序化抽象图形
- 适量空间动画
- Calm 模式下保持静态美感

#### E. Minimal / Photography

- 真实图片优先
- 编辑式图片裁切
- 简洁标题排版
- 网站 Logo 与内容辅助信息

每个母版应该具备多个真正不同的构图变体，而不只是更换颜色。

重点保证：

- 视觉层次清晰
- 不同资源之间有足够区分度
- 文字不溢出
- 中文排版自然
- 英文长标题可处理
- 小尺寸卡片可辨识
- 大尺寸详情仍有精致质感

所有变体必须符合 SHIJI 既有品牌风格。

### 五、任务三：实现真正可用的 Cover Studio 编辑器

在资源详情中加入「编辑封面」入口。

打开后进入独立的封面编辑工作区。

功能至少包括：

#### 1. 风格选择

- 自动推荐
- Editorial
- Spatial
- Code / Developer
- Kinetic
- Minimal
- 现有原始 V5 封面

#### 2. 构图选择

用户可以切换同一风格下的不同母版与布局。

提供预览缩略图。

切换时应即时反馈，不阻塞整个页面。

#### 3. 颜色控制

- 自动推荐色
- 现有 SHIJI 主题色
- 预设调色板
- 允许用户自定义主色
- 对比度自动校验

保持品牌审美，不把颜色控制做成无限制、杂乱的随机配色。

#### 4. 文字控制

支持：

- 自动标题
- 自定义封面标题
- 副标题
- 标题位置
- 排版密度
- 自动换行

自定义封面标题不得直接覆盖资源原始标题。

#### 5. 图片控制

支持：

- 使用真实网站封面
- 使用已保存的本地附件
- 上传新图片
- 使用程序化海报
- 恢复自动选择

图片裁切至少支持 Fit / Fill 和焦点位置调整。

已有图片必须保持引用关系正确，不产生无意义的重复附件。

#### 6. 操作

- 实时预览
- 保存
- 取消
- 恢复自动
- 重新生成推荐变体
- 预览当前画廊显示效果

取消不得写入尚未确认的修改。

保存后资源卡片、详情和相关视图应及时更新。

### 六、任务四：封面生成需要稳定、可重复

相同资源、相同配置必须稳定生成相同封面。

不能在每次刷新、滚动或重新挂载卡片时随机改变样式。

如需要随机种子，应使用可持久化的稳定 seed。

仅在用户明确点击「重新生成」时更换变体。

需要正确处理：

- 资源标题更新
- 自动元数据补全
- 分类修改
- 标签修改
- 手动封面选择
- 图片加载失败
- 资源同步
- 封面回退

必须明确区分：

1. 资源原始内容
2. 系统自动推荐配置
3. 用户显式保存的封面偏好
4. 最终实际显示的封面

用户手动选择的配置始终优先于后台自动补全。

不能出现保存后刷新又恢复默认封面的情况。

### 七、任务五：数据持久化与跨端兼容

这是本轮最重要的技术约束之一。

封面偏好属于用户数据，必须能够可靠保存、恢复和同步。

需要设计明确的 Cover Configuration 数据结构，例如：

- mode
- style
- template
- variant
- seed
- palette
- typography
- imageSource
- imagePosition
- customTitle
- customSubtitle
- version

这些仅表示需要考虑的数据语义，不要求照搬字段名称。

先审查现有 schema 3、ZIP manifest 2、iPhone App Group JSON 与同步协议 1 的实际扩展机制。

优先选择兼容方案，不为新增偏好随意破坏原有资源结构。

如果确实需要版本升级，必须先制定：

- 向前兼容与旧版本读取规则
- 数据迁移
- 回滚
- ZIP 备份与恢复
- Mac / iPhone 同步兼容
- 新旧客户端冲突处理
- 字段级手动编辑保护

不要未经批准直接进行破坏性协议修改。

绝对不能将用户封面偏好仅存放在 localStorage 或搜索派生索引中。

### 八、任务六：保持 V6.3 画廊性能

本轮新增更复杂的封面系统后，不能明显破坏刚刚完成的 V6.3 优化。

必须兼容：

- Gallery Windowing
- 稳定资源 ID
- DOM 挂载与卸载
- 卡片复用
- 高度缓存
- 延迟图片加载
- 滚动锚点
- 详情展开
- Motion Studio / Calm
- Space / Flat
- Reduced Motion

特别验证：

1. 封面变体切换不会引起整个画廊重新构建。
2. 不同封面构图可以正确计算卡片高度。
3. 卡片卸载并重新挂载后配置不丢失。
4. 封面更新不会导致滚动跳动。
5. 编辑器打开时不会触发大量后台渲染。
6. 3D 封面不为离屏卡片长期保留复杂图层。
7. Calm 模式不会保留无意义的持续动画。
8. 不产生重复事件监听器或动画控制器。

优先做组件级更新和缓存失效，而不是直接调用整个应用的全局 render。

不要为了新的封面视觉牺牲 V6.3 的性能成果。

### 九、任务七：提升封面推荐质量

实现可维护的本地 Art Direction 推荐逻辑。

输入真实资源信息，输出若干适合的封面变体。

推荐结果应该具有：

- 内容相关性
- 风格一致性
- 明显的视觉差异
- 可重复性
- 易扩展性

可以设计规则评分机制，而不是只写大量硬编码 if/else。

例如：

标题包含 React、UI、Components 等信息，优先考虑组件风格。

包含 Robotics、ROS、Simulation 等技术信息时，推荐工程或空间构图。

包含 Animation、Motion、GSAP 等信息时，推荐 Kinetic 风格。

但必须避免把关键词识别当作百分之百准确的内容理解。

推荐只是默认建议，用户始终有选择权。

如已有真实高质量封面，默认仍应优先考虑真实图片，不强制改成海报。
