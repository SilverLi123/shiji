# SHIJI V6.2 — Search & Scale

用户本轮完整任务为依据：保留 V5 Hero／Spatial Deck／海报／连续展开和技术栈，升级本地检索、按需查询、跨页全选与大库运行质量。SQLite user_version 3、ZIP manifest 2、iPhone JSON、同步协议 1 及 V6 采集／回执不变。

## 既有语义

搜索为大小写不敏感、空格分隔 AND 子串，覆盖标题、URL、介绍、普通／项目备注、片段、作者、来源、分类、标签、项目、附件名／作者／来源。保留单字、两字中文和代码标点；新增成对双引号短语，用户的 AND／OR 等输入始终按文字处理，不执行 FTS 语法。

筛选包括分类、形式、价格、授权、访问状态、常用、待整理、附件、代码／Prompt、项目后代、标签 all／any／排除、未打标签、未归属项目、有备注、媒体类型、域名及子域、UTC 日期、Lab 相近颜色。回收站、归档项目及智能集合沿用现有含义。

## 存储与兼容

新增本机可重建搜索文档／FTS／变更队列表和 SQL 索引。纯 SQL 触发器记录资源／附件变更，覆盖直接 SQL 的同步、恢复、项目重命名和后台补全。触发器不依赖 Python UDF，不在资源写入事务里运行分词。旧版本仍能写入并留下待索引变更。

FTS5 在每个实际 SQLite 运行时探测；计划使用应用预分词、ASCII 编码的字符 unigram/bigram 倒排，避免依赖 trigram 扩展及其三字限制；候选集仍用原文字面子串精确校验。无 FTS5 时安全降级到相同结果的扫描，不伪装为同等性能。索引只包含派生内容，原资源表权威。损坏时仅重建派生索引。

## 查询与选择

新 Query API 返回每页最多 100 条摘要、总数、版本和下一游标；列表只载入当前累计页面，完整详情按 ID 读取。保留原全量接口供导出／旧客户端使用并批量读取附件，消除 N+1。

游标与查询、排序、资源版本绑定。出现并发修改时明确要求刷新，不静默追加不同版本的页面。跨页全选解析完整匹配 ID 集合；批量修改按选择版本在同一事务重新确认，不退化为当前页。组织选择器用批量轻量摘要，不能偷回全量正文。

## 前端与验收

沿用一个 V5 资源状态和现有动效所有者。防抖、取消过期请求、明确匹配总数、可安全高亮、最近搜索仅保存在本机；键盘快速聚焦、Enter／Esc 支持。详情／编辑必须先取完整内容，不能把截断摘要保存回库。

先以未修改的 V6.1 保存确定性 1K／5K／20K／50K 临时库及源代码副本，保留重复样本；再同环境对照。后台采集及同步差分回归、全文索引损坏／重建、分页／全选竞态必须实测。真实设备和原生性能缺证据时列为未验收，不阻塞本地搜索开发。
