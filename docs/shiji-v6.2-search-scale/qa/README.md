# Isolated QA tools

Run from repository root, with development test dependencies installed in desktop-app. Every dataset/port/credential belongs to a newly created temporary directory. None of these scripts target the formal library or port. Do not substitute formal directories into them.

1. `python3 docs/shiji-v6.2-search-scale/qa/probe.py` verifies SQLite capability.
2. `python3 docs/shiji-v6.2-search-scale/qa/baseline.py` archives and executes commit9433afc, creates1K/5K/20K/50K Store fixtures; manifest `/tmp/shiji-v62-before.json`. This step is intentionally expensive and must precede benchmark copies. Old source is selected from Git, not current source falsely labeled as old.
3. `python3 docs/shiji-v6.2-search-scale/qa/measure.py` copies fixtures and records `/tmp/shiji-v62-after.json`; nine query rounds/five full exports. Avoid parallel builds during strict comparisons.
4. `python3 docs/shiji-v6.2-search-scale/qa/capture_under_load.py` copies after fixtures, runs actual capture commits with controlled network results while searching.
5. `python3 docs/shiji-v6.2-search-scale/qa/serve.py --size 50000` serves the real candidate V5 UI/API on a random port. `--before` serves frozen source; `--size 0` is an independent empty library. State `/tmp/shiji-v62-web-after-50000.json` (corresponding before/size filenames). QA probe only records bounded metadata/timings; never add it to production HTML.
6. Use CUA to open the emitted URL, interact with search, filters, cards and pagination. The fixed QA button starts a30second rAF sample. Scroll with real keyboard/mouse actions. Inspect `#qa-v62-results` or root/metrics.json after completion. It is not compositor FPS. Check60cards and cumulative1020 separately. Reset temporary viewport overrides.
7. Build with `python3 desktop-app/desktop/build.py`, then `python3 docs/shiji-v6.2-search-scale/qa/native.py --size 1000`. A distinct bundle and data directory are emitted. Open through CUA. Native QA adds only process attribution and the buffered probe. It never uses formal pairing preferences. Verify hidden/focus before claiming foreground measurements.
8. Existing `docs/shiji-v5.1/qa/process_sample.c` collects per-process Mach CPU/physical footprint after native WebContent attribution. RSS alone is insufficient; shared GPU allocations remain separate.

The local `desktop-app/dist/shiji-v62-search-interaction.mp4` is a22-frame **CUA screenshot-sequence replay**, encoded with actual capture timestamps by `encode-captures.swift` (22captures/15.26seconds,1246×700). It shows real search and one card open, not synthetic Demo animation. It is low cadence, not continuous native screen recording and never performance evidence. Source frames live in `/tmp/shiji-v62-video-zoDL8H`; encoder arguments are capture directory and output MP4. Video remains in ignored dist rather than growing Git history; publish as an approved CI Artifact when needed. Still screenshots/raw measurements are versioned.

Tests: from desktop-app, `python3 -m unittest discover -s tests -v`, `npm test`; CI partitions via `python3 tests/run-ci.py --suite portable` and `--suite native`. From root run mobile-app/Tests/run.py and sync_integration.py with Python, plus the existing100URL recovery script and native evidence parser/probe checks in workflow. Full tests use disposable data; native simulator/real-browser installation acceptance remains separate.
